# Coupon benchmark: repeated runs

The [original demo](../README.md) was one run per variant. This folder repeats it with a script, so the numbers come with their spread and anyone can re-run them.

## Variants

| Variant | Prompt | Model · effort |
|---|---|---|
| `vibe-medium` | the task sentence alone | Opus · medium (the default) |
| `vibe-xhigh` | the task sentence alone | Opus · xhigh: same effort as the crew's planner, skeptic and reviewer |
| `crew` | `/crew:ship` + the task sentence | main session Opus · default; each agent uses the model and effort in its own file |

The task sentence, the same for every run:

> Let checkout accept several coupon codes at once: `checkout(items, codes?: string | string[], now?)`. A single string must keep working.

Nobody answers the crew's checkpoint during a benchmark, so the crew prompt adds one fixed operator note: take the planner's default for every open question, fold in the skeptic's changes, list those decisions, don't commit. This is what the operator did by hand in the original run.

## What each run does ([run.py](run.py))

1. Copies [../base](../base) into a fresh folder outside this repository and commits it to a new git repo.
2. Runs `claude -p` headless in it, with:
   - a sanitised environment: no GitHub or cloud credentials, no link to the session that started it;
   - `--permission-mode acceptEdits` and a Bash allowlist for `npm test`, `npm run`, `npx vitest`, `npx tsc`, read-only `git`, `ls` and `node -e`;
   - no MCP servers, no web, and no Skill, Workflow or Artifact tools;
   - reads of this repository denied, so no run can see the hidden tests.
3. Saves the real patch (`git diff` including new files), the gzipped transcript, the final answer and `result.json` to `results/<variant>-<n>/`.
4. Scores the result with [score.py](score.py): its own tests, `tsc --noEmit`, then the 12 [hidden tests](../hidden/acceptance.test.ts) and the [probe](probe.test.ts), both copied in only now.
5. Checks the transcript for any mention of the hidden tests or the original run.

The probe adds two checks that the hidden tests don't cover:
- **Order-dependent price:** the same coupons in every order, on 2 786 carts from 5.00 to 200.00, once with two percent coupons (WELCOME10 and SUMMER15, on a date when both are valid) and once with WELCOME10, SAVE5 and GIFT25. A run counts as order-dependent when any cart gets two totals. For a vibe run that applies coupons in the order given *on purpose* and says so, this is a design choice rather than a bug; the transcripts show which.
- **Free cart:** GIFT25 + SAVE5 on a 30.00 cart. A total of 0 isn't wrong in itself. It is the business question the crew's skeptic raised in the original run.

Cost is `total_cost_usd` as Claude Code reports it at list price, subagents included.

## Results

See [results/SUMMARY.md](results/SUMMARY.md), generated by [summarize.py](summarize.py). Each run's patch and transcript are next to it.

## Re-run

```bash
cd examples/coupon-demo
python3 bench/run.py vibe-medium 6
python3 bench/run.py crew 6
python3 bench/summarize.py
```

`crew` loads `plugins/crew` from this checkout with `--plugin-dir`, so it measures the agents as they are in the repo. Runs need a logged-in Claude Code and cost real money: see the cost column.

## Limits

- Five runs per variant show the spread, not a statistically solid difference.
- One small task in one language. It says nothing about large codebases.
- The runs ran inside a Claude Code cloud session. Its extra org plugins were installed but the tools listed above were denied to every variant alike.
- The hidden tests and the probe were written by the author of the crew, and the hidden tests are older than these runs ([git history](https://github.com/kavicka/claude-crews/commits/main/examples/coupon-demo/hidden)).
